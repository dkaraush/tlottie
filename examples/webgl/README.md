# OpenGL and WebGL2 setup

The `opengl` feature exposes `tlottie::opengl::OpenGlRenderer` for OpenGL 3.3
and OpenGL ES 3.0 hosts. The host owns the window/context and constructs a
`glow::Context`; tlottie draws into the framebuffer that is bound at render
time.

```sh
cargo build --no-default-features --features opengl
```

The `webgl` feature includes `opengl` and the existing raw `wasm` exports, then
adds the generated `WebGlRenderer` canvas binding. Build the browser package:

```sh
cargo install --root target/tools wasm-bindgen-cli --version 0.2.126 --locked
./examples/webgl/build.sh
python3 -m http.server 8000
```

Open <http://localhost:8000/examples/webgl/>. The example keeps its tiny app
code inline in HTML. `pkg/tlottie.js` is generated by `wasm-bindgen`; there is
no handwritten tlottie WebGL shim to copy into an application.

WebAssembly cannot call browser Web APIs, including WebGL, without JavaScript
host bindings. Emscripten also generates a JavaScript runtime, so it does not
remove that boundary. `wasm-bindgen` and `web-sys` keep the boundary generated,
typed, and Rust-native.
